# Spend Insights

An owner-private statement explorer. It supports local Numbers, Excel, CSV, TSV, text PDFs, scanned PDFs and clear JPG/PNG/WebP statement photos. The current release assumes INR and English printed transaction tables. Unknown layouts, poor scans, handwriting and other currencies are not universally supported; users review column mappings, source totals, warnings and OCR output before importing.

The original private dataset retains its existing storage key and 1,589 transactions. New analyses start empty and use independent browser-storage keys; switching analyses preserves each dataset, category overrides and merchant rules. JSON backup/restore acts on the current analysis. This remains the owner's private site, not a public multi-user service.

All processing stays in the browser. PDF.js 6.4.299 extracts selectable text and renders scanned pages; Tesseract.js 7.0.0 runs OCR using vendored English recognition assets. There are no runtime external analytics, OCR endpoints or model APIs. Limits: 20 MB per file, 100 PDF pages, 20 OCR pages, 8 million rendered pixels per page. Recognition needs review even when balances reconcile. Common references and UPI addresses are masked where detected; sanitized transactions still contain private financial information.

`core.mjs` owns normalization, conservative category suggestions, duplicate detection and reconciliation. Malformed transaction rows remain visible as errors; the raw extraction table is editable. Debits/credits, ambiguous dates, conflicting direction flags and duplicate column mappings are checked. The original data and fingerprints remain compatible. Bank and card activity remain distinct, and card settlements are not treated as purchases.

`explorer.mjs` derives account → category → merchant relationships from effective transactions. Nodes and links retain supporting transaction IDs and source rows/pages. Selected nodes open evidence; question chips, search, account/date/category filters and direction controls change the view. Exports include the complete matching graph, including nodes hidden by visual caps. The original Browse connections view remains available, including graph exports.

The default Ask & connect view adds a persistent SVG graph with pan/zoom, node focus, clickable answer references and statement evidence. `query-engine.mjs` parses a bounded set of questions into explicit filters and exact cent-based aggregations. Follow-ups preserve scope; switching analysis, changing data or top-level filters clears chat context. Calendar-month comparisons use the latest statement month, and partial coverage is disclosed. Unsupported calculations are rejected rather than silently approximated. Answers use templates, not a generative language model.

Optional semantic search runs **EmbeddingGemma 2 locally in a Web Worker**. Transformers.js is pinned to 4.3.1 and vendored using `node scripts/vendor-model-runtime.mjs`; the ONNX model revision is pinned in `semantic-worker.mjs`. Only the text encoder loads (`q4`, WebGPU, batches of 4, maximum 256 tokens). Google’s multimodal model is used on extracted transaction text here; it does not directly OCR or embed uploaded page images. Model/tokenizer download is about 207 MB, plus about 26 MB of ONNX runtime, fetched from Hugging Face and pinned jsDelivr URLs only after Enable. Browser caching is used when available. No transaction data is sent to those servers. There is no hosted inference API, API key, or telemetry. Unsupported WebGPU/download failures leave structured questions usable.

Semantic documents group each merchant/category pair with up to three narration samples. Retrieval selects at most five groups above a heuristic similarity cutoff, then computations include every matching transaction in those groups. This is candidate discovery, not guaranteed exhaustive semantic matching or verified ownership. Dashed links and removable group chips distinguish suggestions; similarity is not displayed as a confidence percentage. Embeddings remain in worker memory and are cleared when the analysis scope changes. The model warm-up validates finite vectors; errors, cancellation and operation generations prevent stale answers.

Runtime sources: [Transformers.js 4.3.1](https://github.com/huggingface/transformers.js/releases/tag/4.3.1), [EmbeddingGemma 2 ONNX model](https://huggingface.co/onnx-community/embeddinggemma-2-ONNX), [Google model card](https://ai.google.dev/gemma/docs/embeddinggemma/model_card_2).

Run `npm test` for parser fixtures, source totals, UI controllers, graph evidence and geometry extraction. Optional `STATEMENT_FILE` enables the original Numbers-file check. Local Chrome QA covers synthetic multi-page text PDF, scanned PDF and photo extraction, raw-table correction, review acknowledgement, duplicate retention, graph export, workspace isolation/reload and responsive layouts. Synthetic fixtures validate supported table shapes, not every bank's statement format.

The existing card planner is an editable scenario. Bank descriptions do not establish issuer category codes, card acceptance or reward eligibility.
